# Domain docs

## Before exploring

This repo uses a single-context layout:
- Read root `GLOSSARY.md` if present.
- Read relevant decisions in `docs/adr/` if present.

If these files are absent, proceed silently. Domain-modeling workflows
create them lazily when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms for domain concepts in issues, proposals,
hypotheses, and tests. Reconsider unfamiliar terminology or note a real
gap for domain modeling.

## Decisions

Explicitly flag proposals that contradict an existing ADR, identifying
the ADR and explaining why it should be reconsidered.
